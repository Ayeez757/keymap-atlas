# 设计说明

## 一句话

快捷键清单的价值不在「列出来」，而在**哪一条是真的**。所以整个程序围绕
「证据」组织，而不是围绕「配置解析」组织。

## 为什么证据要分优先级

同一件事有多个来源会给出互相矛盾的答案：

| 来源 | 声称 | 实际 |
|---|---|---|
| `/proc` KEY 位图 | 这把键盘有音量加键 | 按下去没反应 |
| HID 描述符 | 键盘页 `0x00–0xff` 全都支持 | 只是通用数组，不代表有实体键 |
| 你按了一下 | 有 | 有 |

矛盾时必须有一条明确的裁决顺序，否则就是随机结果。本项目的顺序写在
`src/keymap_atlas/evidence.py` 的 `judge()` 里，从上到下：

1. `observed` — 探针实测按出过（最强，直接观测）
2. `hid` = yes — 描述符**点名**了该 usage（比位图强，因为点名是逐条列举）
3. `absent` — 用户手工标记（人的判断高于文件推断）
4. `hid` = no — 描述符完全没覆盖（可以断言没有）
5. `observed_stale` — 实测记录来自旧键盘（不是否定，只是过期）
6. `hid` = unk / maybe — 泛型范围或窄范围
7. `bitmap` — `/proc` 位图（最弱，仅作兜底）

第 6 步有个容易搞反的细节：**普通按键**（字母、数字、F 键）只被泛型范围覆盖是
正常的——几乎所有 USB 键盘都这么写。所以这类键继续落到第 7 步用位图判定，
位图对它们可信。只有 **XF86 媒体键 / 亮度键** 才真的无法从文件判定，必须留 ❓。

## 为什么用键盘指纹

用户会在几把键盘之间来回换。指纹 = `sha1(排序后的 (name, vendor, product, 按键数))[:16]`。

- 换键盘 → 指纹变 → 旧实测记录降级为 `observed_stale`（**不删除**）；
- 换回来 → 指纹复原 → 旧记录自动重新生效。

删掉记录是最省事的做法，但那意味着用户每换一次键盘就要重新按 66 个键。

## 为什么不弹通知轰炸

v0.1.0 修的真实 bug：systemd 服务的 cwd 是 `$HOME`，而旧脚本的产物目录默认
`os.getcwd()`，于是产物写到了 `$HOME`，脚本却去仓库目录读指纹 —— 永远「不相同」，
每收到一条 udev 事件就重建 + 弹通知，一分钟 30 次。

现在的约束是三条，缺一不可：

1. 显式传 `--outdir` / `--state-dir`，不依赖 cwd；
2. 重建之间有 5 秒单调时钟冷却；
3. **重建后断言**「落盘指纹 == 当前指纹」，不等就只警告一次，不循环。

## 为什么产物是单文件 HTML

用户最常干的事是「搜一下」。所以 HTML 把 CSS 和 JS 全部内联，`tr[data-b]` 上带一条
小写检索串（功能 + 键位 + 备注 + 拼音别名），页内过滤。不需要服务器、不需要联网、
可以直接丢进 U 盘。

代价是 HTML 体积（本机约 120 KB / 338 条），换来的是零依赖可分发。

## 已知限制

- **合成器只支持 niri**。Hyprland / Sway / KDE 的键位配置格式完全不同，
  没实现就是没实现，不假装支持。
- KDE 与 GNOME 层标「未生效」：它们读的是配置文件，但当前会话不是那个桌面，
  照着按不会有反应。列出来是为了迁移时参考。
- 无法枚举浏览器 / Electron / GTK-Qt accel / 键盘固件 Fn 组合 / portal
  GlobalShortcuts，原因逐条写在报告最后一节。
