广告
问题

配置里写了，不等于按得出来

列快捷键的工具不少，但几乎都不处理这个前提。

每个键盘在 /proc/bus/input/devices 里都有一张「按键能力位图」， 看着像真相，其实经常是假的：很多 USB 键盘在 HID 描述符里只声明一个 泛型全范围数组（键盘页 0x00–0xff、Consumer 页 0x0–0x33c），内核就把整段区间全部标成「有这个键」。

于是位图声称你有音量加键，按下去却毫无反应。反过来，PrintScreen 在 evdev 里 是 KEY_SYSRQ（码 99），而 210 是 Consumer 接口声明的假象—— 按位图找，永远找不对。

本项目把判断依据排成一条优先级链，每一级都能说清出处， 判不出来就老实说判不出来。

别人的工具告诉你「Super Q 关闭窗口」。 这里还告诉你「你这把键盘上没有音量加键」以及凭什么。
判定

六条依据，按可信度排队

同一件事有多个来源会给出互相矛盾的答案，没有明确顺序就是随机结果。

  1. 探针实测按出过可按
  2. HID 描述符点名了该 usage可按
  3. 你标记「我这把键盘没有」按不出
  4. HID 描述符完全没覆盖按不出
  5. 只被泛型范围覆盖，文件层面无从判定存疑
  6. /proc 位图声称有可按，但注明未实测

实测记录属于上一把键盘时不会删除，而是降级为「存疑」； 换回原键盘它们会自动重新生效。删掉最省事，但那意味着每次换键盘都要重按 66 个键。

广告
安装

一行命令，从源码装

只有一份 Python 包，没有编译步骤，也没有第三方依赖。

bash 
$ git clone https://github.com/Ayeez757/keymap-atlas
$ cd keymap-atlas
$ pip install --user .
$ keymap-atlas report --outdir ~/快捷键

不想装也行

直接用源码跑，不污染环境：
PYTHONPATH=src python3 -m keymap_atlas report

图形探针（可选）

真实按键检测需要 GTK4 的 Python 绑定，这是唯一的可选依赖。
Fedora：sudo dnf install python3-gobject gtk4
Debian / Ubuntu：sudo apt install python3-gi gir1.2-gtk-4.0

换键盘自动重算

装成 systemd 用户服务后，插拔键盘会自动重建。只要 udevadm，不需要 root。

用法

三条命令走完

看清单、补实测、查表。日常只会用到第三条。

  1. 看清楚现在有什么 keymap-atlas layers 列出这台机器能解析到哪几层、各多少条； keymap-atlas doctor 告诉你哪些证据源可用。
  2. 让判定变准 keymap-atlas probe 开一个小窗口，把你关心的键按一遍。 实测结果优先于任何文件推断。探测期间会临时抑制合成器快捷键，退出时自动复位。
  3. 查表 keymap-atlas lookup 音量、lookup yl（拼音首字母）、 lookup jt --all。想要弹窗就用 scripts/keys-lookup.sh， 选中即复制到剪贴板。
为什么

判定为什么分三态

因为「不确定」是真实信息，抹平它会骗人。

✅ 可按

实测按出过，或 HID 描述符点名了该键。两者都能追溯到具体证据。

❓ 存疑

只被泛型范围覆盖，文件层面无法判定；或者实测记录来自上一把键盘。请按一下。

⛔ 按不出

描述符完全没覆盖，或你明确标记过这把键盘没有该键。不必再试。

FAQ

常见问题

为什么我的 PrintScreen 不出现在表里？

evdev 里打印屏幕键是 KEY_SYSRQ（码 99），而不是 210。很多键盘的 Consumer 接口会在描述符里声明 210，于是位图看起来「有」，实际按不出来。 工具会把它标成三态里的某一档，而不是假装有。

必须以 niri 为桌面才能用吗？

不是。六层里只有第一层依赖 niri。缺哪一层就整层跳过，不会因为找不到文件就崩。 输入法、终端、KDE、GNOME、内核层都是独立探测的，任意组合可用。 其他合成器（Hyprland / Sway）的配置格式不同，未实现，也不假装支持。

为什么不读浏览器里的快捷键？

浏览器的快捷键编译进程序，或者存在 profile 的加密库里；扩展的快捷键又在各自的 存储里。没有统一导出接口，硬猜就是编造。

会修改我的配置吗？

不会。程序只读配置文件；会写的地方只有输出目录，以及状态目录 （~/.config/keymap-atlas/）里保存实测记录和键盘指纹。 指纹是设备名与按键数的 SHA-1 前 16 位，不含任何个人信息。

换键盘以后要重新按一遍吗？

不用全部重按。指纹改变后旧记录标记为「来自旧键盘」；你换回原键盘时它们会自动 重新生效。只有新键盘上没验证过的键需要按。

为什么表格里有的行标着「未生效」？

因为那层属于别的桌面环境。你在 niri 会话里按 KDE 的快捷键当然没反应， 但迁移过去时它就是你要的参照。
