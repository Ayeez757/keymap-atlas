赞助商

它解决什么问题

列快捷键的工具不少，但几乎都不处理一个前提：配置里写了，不等于按得出来。

每个键盘在 /proc/bus/input/devices 里都有一张「按键能力位图」。看着像真相， 其实经常是假的：很多 USB 键盘在 HID 描述符里只声明一个泛型全范围数组 （键盘页 0x00–0xff、Consumer 页 0x0–0x33c），内核就把整段区间 全部标成「有这个键」。于是位图声称你有音量加键，按下去却毫无反应。

本项目把判断依据排成一条优先级链，每一级都能说清出处，判不出来就老实说判不出来。

优先级依据结论
1探针实测按出过✅ 可按
2HID 描述符点名了该 usage✅ 可按
3你标记「我这把键盘没有」⛔ 按不出
4HID 描述符完全没覆盖⛔ 按不出
5只被泛型范围覆盖❓ 存疑，需实测
6/proc 位图声称有✅ 但注明「未实测」

六个可静态解析的层

下表的数字取自一台真实的 Fedora + niri 机器，可以直接对照。

层来源条数状态
1 · 合成器层~/.config/niri/**/*.kdl137生效
2 · 输入法层~/.config/fcitx5/config7生效
3 · 终端应用层~/.config/ghostty/config6生效
4 · 内核 / 硬件层logind 属性、sysrq16生效

未生效的层照样列出来——迁移桌面环境时最需要它。还有一层故意不列： 浏览器 / Electron 应用内快捷键、GTK-Qt 的 accel、键盘固件里的 Fn 组合、 portal GlobalShortcuts（按会话隔离，读别人的会话会被 Access denied）。

下载与安装

推荐从源码安装，只有一份 Python 包，没有编译步骤。

git clone https://github.com/Ayeez757/keymap-atlas
cd keymap-atlas
pip install --user .
keymap-atlas report --outdir ~/快捷键

不想装也能直接跑：

PYTHONPATH=src python3 -m keymap_atlas report --outdir ~/快捷键

图形探针（真实按键检测）需要 GTK4 的 Python 绑定，这是唯一的可选依赖：

# Fedora
sudo dnf install python3-gobject gtk4
# Debian / Ubuntu
sudo apt install python3-gi gir1.2-gtk-4.0

单文件 HTML

产物 all-shortcuts-zh.html 自带搜索框，离线可用，可以直接丢进 U 盘。

TSV / JSON

shortcuts-index.tsv 六列，方便接自己的脚本或表格工具。

热插拔自动重算

装成 systemd 用户服务后，换键盘自动重建；只要 udevadm，不需要 root。

三条命令走完

  1. 看清楚现在有什么
    keymap-atlas layers 列出这台机器能解析到哪几层、各多少条； keymap-atlas doctor 告诉你哪些证据源可用。
  2. 让判定变准
    keymap-atlas probe 开一个小窗口，把你关心的键按一遍。实测结果优先于 任何文件推断；换上另一把键盘，旧记录会自动降级为「存疑」而不是被删掉。
  3. 查表
    keymap-atlas lookup 音量、lookup yl（拼音首字母）、 lookup jt --all。想要弹窗就用 scripts/keys-lookup.sh， 选中即复制到剪贴板。

判定为什么分三态

因为「不确定」是真实信息，抹平它会骗人。

✅ 可按

实测按出过，或 HID 描述符点名了该键。

❓ 存疑

只被泛型范围覆盖，文件层面无法判定；或者实测记录来自上一把键盘。

⛔ 按不出

描述符完全没覆盖，或你明确标记过这把键盘没有该键。

常见问题

为什么我的 PrintScreen 不出现在表里？

evdev 里打印屏幕键是 KEY_SYSRQ（码 99），而不是 210。很多键盘的 Consumer 接口会在描述符里声明 210，于是位图看起来「有」，实际按不出来。 工具会把它标成三态里的某一档，而不是假装有。

必须以 niri 为桌面才能用吗？

不是。六层里只有第一层依赖 niri。缺哪一层就整层跳过，不会因为找不到文件就崩。 输入法、终端、KDE、GNOME、内核层都是独立探测的，任意组合可用。

为什么不读浏览器里的快捷键？

浏览器的快捷键编译进程序，或者存在 profile 的加密库里；扩展的快捷键又在各自的 存储里。没有统一导出接口，硬猜就是编造。

会修改我的配置吗？

不会。程序只读配置文件；会写的地方只有输出目录，以及状态目录 （~/.config/keymap-atlas/）里保存实测记录和键盘指纹。

换键盘以后要重新按一遍吗？

不用全部重按。指纹改变后旧记录标记为「来自旧键盘」；你换回原键盘时它们会自动 重新生效。只有新键盘上没验证过的键需要按。

为什么表格里有的行标着「未生效」？

因为那层属于别的桌面环境。你在 niri 会话里按 KDE 的快捷键当然没反应， 但迁移过去时它就是你要的参照。
